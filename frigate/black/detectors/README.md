# Дополнительный детектор двухколёсного транспорта

`kugoo.py` добавляет предложения COCO `bicycle` к результатам штатного
YOLOv9-t-320. Все заполненные строки основного детектора сохраняются;
добавление занимает только свободные строки и подавляет дубли существующих
`bicycle`/`motorcycle`. При нехватке GPU или ошибке сохраняется основной результат.

Проверенные дополнительные веса — YOLO11n, один класс, ONNX FP32 с входом
`[2,3,640,640]`: текущая область и её уменьшенная до 320 и возвращённая к 640
копия. Оба масштаба обрабатываются одним вызовом CUDA, затем объединяются NMS.
Веса, фотографии, видео и галерея хранятся отдельно от Git. Нужны именно
проверенные веса; произвольный ONNX с подходящим размером не заменяет проверку.

Дополнение закреплено за существующей P40 по UUID. Ограничения: CUDA без CPU
fallback, арена 1536 МиБ, свободно не менее 2048 МиБ, перед загрузкой 3584 МиБ,
загрузка GPU перед вычислением менее 25%, интервал не менее 0,5 секунды на камеру.
Фактические провайдеры первого вычисления проверяются по профилю ONNX Runtime.
Состояние и счётчики, включая отдельные счётчики камер, доступны внутри контейнера в
`/tmp/kugoo-detector-status.json`; изображения туда не сохраняются.

Дополнение работает с первого допустимого запроса без задержки запуска.
Для каждого штатного кадра добавляется одна квадратная область обзора размером
до 960 пикселей в исходном разрешении. Frigate выбирает минимальную область
320 пикселей даже для больших моделей; такой фрагмент может обрезать самокат.
Область дополнения обходит кадр без разметки или заданных координат объекта,
включая кадры без движения и подтверждённых объектов.
Без найденного транспорта область обзора меняется каждый кадр, чтобы не
задерживать обнаружение короткого проезда. При наличии track индекс обхода
продвигается раз в четыре кадра, поэтому все шесть областей большой камеры
доступны и при постоянном track внизу.
При наличии двухколёсного track или предложения, полученного за последние 8 секунд,
три из четырёх кадров получают область с его центром, четвёртый продолжает
обход. Предложение ещё не является событием: повторные попадания по-прежнему
подтверждает штатный tracker. Сохранённая область помогает повторному поиску после
пропуска GPU и не подаётся tracker как новое обнаружение. Штатные области движения сохраняются.
Области предыдущего кадра не задерживают текущий. Не более одного вычисления
на кадр каждой из двух измеренных камер с частотой анализа 1 FPS; ранний
запрос возвращает основной результат без ожидания.

`kugoo_snapshots.py` дополняет штатный выбор снимка только для `bicycle` и
`motorcycle`: спустя 5 секунд допустим новый реальный кадр с оценкой от 0,7,
площадью не менее 90% прежней и без обрезания краем кадра. Штатный tracker
по-прежнему требует настоящий объект в текущем кадре. Это даёт классификатору
разные снимки даже при неизменной оценке лучшего кадра. Полноразмерный JPEG
читается сразу с проверкой точного времени; ожидание сегмента записи для него
не требуется. Для автомобилей,
котов и остальных классов действует исходный выбор Frigate.

Полноразмерный JPEG события от 1280×720 используется сразу после проверки
времени кадра. Для малых снимков сохраняется извлечение из записи.
В этом режиме отслеживание двухколёсного транспорта ограничено двумя
проверенными камерами; остальные классы и запись других камер сохраняются.
Дополнительная модель получает точное имя камеры, время кадра, текущие области
и координаты двухколёсных tracks из
штатной очереди Frigate через адаптеры `object_detection/base.py` и `video/detect.py`.
Обработка не ожидает разрешённого интервала внутри общего детектора;
запросы остальных камер сразу используют основной результат. Результаты
упорядочены по оценке, как требует штатный ранний выход Frigate.

## Включение

1. Разместить проверенные веса в
   `/opt/frigate/config/model_cache/kugoo-yolo11n-pyramid.onnx`, а `kugoo.py` —
   в `/opt/frigate/detectors/kugoo.py` с доступом на чтение контейнеру.
   Рядом разместить `kugoo_snapshots.py`. Из того же закреплённого образа извлечь
   `/opt/frigate/frigate/track/tracked_object.py` и обработать его
   `prepare_snapshot_patch.py SOURCE /opt/frigate/detectors/tracked_object.py`.
   Аналогично извлечь `/opt/frigate/frigate/object_detection/base.py` и выполнить
   `prepare_snapshot_patch.py SOURCE /opt/frigate/detectors/detection_base.py --detector-context`.
   Модуль `/opt/frigate/frigate/video/detect.py` обработать командой
   `prepare_snapshot_patch.py SOURCE /opt/frigate/detectors/video_detect.py --video-context`.
   Генератор прекращает работу при изменении ожидаемого контракта; исходный
   код Frigate в образе не редактировать. Подготовленные файлы подключаются overlay.
2. Преобразовать текущий конфиг через `prepare.py --kugoo-only` и проверить его
   тем же закреплённым образом Frigate с подключённым `compose.kugoo.yml`.
3. Добавить `/opt/frigate/compose.kugoo.yml` к действующему `COMPOSE_FILE` в
   `/opt/frigate/runtime.env`. Сохранить остальные действующие файлы Compose.
4. Задать `FRIGATE_OBJECT_POLL_SECONDS=2` в окружении классификатора.
5. Запустить автономный откат, перезапустить сервисы и проверить с другого узла
   API, запись всех камер, FPS, пропуски, GPU и работу обычных объектов.
6. Только после приёмки отменить таймер отката.

Режим меняет размер входной области модели на 960. Для двух измеренных камер
используется полный кадр 1280×720 и 1920×1080 с анализом 1 кадра/с. Непрерывная
запись, подключения камер, пороги объектов и галереи сохраняются. Изменение
областей и частоты анализа требует проверки обычных автомобилей и котов;
сохранение строк детектора само по себе не доказывает прежнюю полноту обнаружения.

## Проверка

Фиксированный набор из девяти полных изображений: не менее 7 попаданий при IoU
не менее 0,5, пороге 0,7 и неизменном `min_score=0.5`. Дополнительно нужен
нативный прогон сохранённых видео: Frigate сам создаёт трек и снимки, worker
получает два возрастающих `snapshot_frame_time`, делает два совпадения и
записывает метку с последующим чтением API. Ручные события, голоса и метки
результатом не считаются. Фрагмент V6 из обучающей демонстрации подтверждает
связность потока; независимую оценку качества им не подменяют.

Проверки сохранения строк, отказов GPU и очереди без блокирующего ожидания
запускаются внутри существующего образа Frigate:
`python3 frigate/black/detectors/test_kugoo.py`.
