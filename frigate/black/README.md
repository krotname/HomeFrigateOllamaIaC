# Frigate 0.18 на Black, архив на White

Проверенный пробный запуск: три камеры по 3 кадра/с, около 734 МиБ VRAM для
детектора и NVDEC. Русский запрос к Jina v2 на CPU занимает около 6,5 секунды
на Xeon E5-1650 v3; этот поиск экономит видеопамять ценой задержки.

На Black работают Frigate, детектор YOLOv9-t через ONNX CUDA и NVDEC. Три основных
потока записываются без перекодирования и с исходным аудио на прежний диск White.
Русский семантический поиск использует квантованный Jina v2 на CPU; FaceNet также
работает на CPU. Они не занимают видеопамять интерактивных моделей. SQLite, кеш
моделей и очередь описаний находятся на локальном диске Black, не на NFS.

`prepare.py` преобразует актуальный конфиг, сохраняя подключения, размеры кадров,
учётные данные, go2rtc, аутентификацию и имена камер. `--staging` отключает запись
для проверки до переключения. `--cpu` создаёт профиль без CUDA для восстановления.
Модель детектора берётся из проверенного существующего кеша White; повторная
сборка модели не нужна. Основная версия образа закреплена; в live `.env` указывается
её точный digest после загрузки.

Служба `frigate-black.service` зависит от `media-frigate.mount` и проверяет точку
монтирования перед запуском. Docker не запускает этот контейнер самостоятельно
при загрузке. Используется hard NFSv4: отсутствие White не должно приводить к
записи в пустой каталог на системном диске Black. Экспорт White допускает только
адрес Black. Прежние URL и Basic auth остаются на nginx White; RTSP и WebRTC
передаются на Black через `white-streams.conf` в главном контексте nginx.
`protect-backend.sh` перед запуском контейнера ограничивает Docker-порт 18971
проверенным адресом источника White через DOCKER-USER. Адрес, увиденный в соединении
на Black (после NAT, если он есть), записывается в `/opt/frigate/proxy-sources`.
Проверяются успешный доступ с White и отказ с другого узла LAN. Правило касается
только этого порта; локальный API очереди остаётся на 127.0.0.1:15000.

OCR автоматически спит после пяти минут без запросов и загружается при обращении.
При включённом `OCR_LLM_IDLE_ENABLED` API сначала выполняет однотокенный запрос:
это проверяемый обход гонки перехода в сон llama.cpp #29689 перед обработкой
большого изображения. Health checks не пробуждают модель.
Whisper освобождает GPU после аналогичного простоя. Описания используют существующий
Qwen3-VL, одну ограниченную очередь и не заменяют вручную написанный текст. OCR имеет
приоритет перед очередью. Проверки ASR и слотов общего Qwen также откладывают
описания до простоя; ключ читается из существующего runtime-файла только для
локального запроса `/slots`. Общий Qwen сохраняет прежнюю конфигурацию и доступность.
При отказе одной GPU контроллер останавливает общий Qwen. Недоступный обязательный
probe `/slots` откладывает описания даже при idle ASR: OCR и ASR на одной оставшейся
карте обслуживают запросы без фоновой генерации. Health ASR сам по себе не является
резервированием GPU.
`caption-compose.yml` запускает отдельный worker без GPU, с постоянной SQLite
очередью на `/var/lib/frigate-caption`, пределом 500 событий и сроком хранения три дня.
Перед запуском выполнить `install -d -m 700 /var/lib/frigate-caption`. Worker явно
работает с UID 0 без capabilities: ему нужны собственная очередь и чтение существующего
ключа root:0600. Остальная файловая система контейнера read-only, ключ смонтирован
read-only; Compose не создаёт отсутствующие bind-пути автоматически.

После переключения `/opt/frigate/moved-to-black` на White предотвращает повторный
запуск старой Ansible-роли. Камерный watchdog переносится на Black. Старый recorder
и его конфиги нужны для отката, но остаются остановленными с выключенными timers.

Порядок переключения: сначала проверить staging, NFS и доступ в обе стороны,
подготовить локальную временную точку отката на White и испытать автономный timer.
Затем остановить старого писателя и его watchdog, перенести закрытую SQLite с WAL,
запустить Black, проверить новые сегменты всех трёх камер и только после этого
переключить nginx. Не запускать два писателя одного архива. Таймер отката отменять
после проверки с ноутбука. Перед изменением зафиксировать состояние в проектном
checkpoint; не включать туда конфиги с паролями.

`rollback-black.sh` и `rollback-white.sh` работают из двух transient systemd timers.
Black останавливает писателя, проверяет Docker и атомарно пишет токен операции в
архив. White принимает только этот токен и затем возвращает nginx и старый recorder.
Перед подтверждением Black передаёт закрытую актуальную SQLite и WAL временным tar
через NFS; остановленный White восстанавливает её до запуска. Поэтому события,
созданные на Black до отката, сохраняются в индексе. Испытание при уже работающем
White не заменяет его открытую БД.
Без подтверждения остановки Black он не создаёт второго писателя. Скрипты и
временные конфиги отката сохраняются до успешной приёмки переключения.

На обоих узлах создать `install -d -m 700 /run/frigate-black-cutover`, записать в
`token` одинаковый уникальный токен операции и установить соответствующий скрипт
`rollback-black.sh` или `rollback-white.sh` в этот каталог с режимом 700. На White
скопировать туда текущие `/etc/nginx/sites-available/home-ai-proxies`,
`/etc/nginx/sites-available/frigate-white-domain` и `/etc/nginx/nginx.conf`, сохранив
имена файлов. Эти временные копии содержат состояние отката и не отправляются в Git.

1. При остановленном Black и работающем White испытать `sudo ./arm-rollback.sh black 30`
   на Black и `sudo ./arm-rollback.sh white 40` на White. Проверить журналы обеих служб,
   остановленный и disabled Black, работающий старый recorder и nginx White.
2. Удалить испытательные transient timers командами `systemctl stop frigate-black-rollback.timer`
   и `systemctl stop frigate-white-rollback.timer` на соответствующих узлах. Для реальной
   операции установить новый одинаковый token; прежний marker не подтверждает новый откат.
3. Перед переключением запустить `sudo ./arm-rollback.sh black 600` и
   `sudo ./arm-rollback.sh white 650` на соответствующих узлах и проверить active timers.
   После этого включить и запустить новую службу Black в штатном порядке переключения.
4. После независимой проверки новых сегментов и прежних URL остановить оба timer.
   Проверить `systemctl is-active` (inactive) и отсутствие выполняющегося rollback service.

Откат Black выполняет `disable --now`, поэтому перезагрузка не создаст второго
писателя после восстановления White. Повторное переключение требует явного
`systemctl enable --now frigate-black.service`.

Исполняемые шаги установки (из копии проверенного `main` на соответствующем узле):

1. На Black: `sudo python3 frigate/black/deploy.py black --token <UUID> --proxy-source <White-IP>`.
   Можно повторить `--proxy-source` для адреса White после NAT. Команда устанавливает
   mount/service, исполняемый pre-start hook, существующий camera watchdog и его timer,
   каталог очереди и состояние отката. Recorder пока не запускается.
2. На White: `sudo python3 frigate/black/deploy.py white-prepare --token <тот же UUID>`.
   Затем испытать timers указанным выше способом, повторить подготовку с новым UUID
   и вооружить реальные timers на обоих узлах.
3. На White: `sudo python3 frigate/black/deploy.py white-stop`. Команда создаёт fence
   `/opt/frigate/moved-to-black` до остановки, останавливает timers и выполняющиеся
   watchdog services, затем подтверждает остановку recorder.
4. На рабочей станции: `node frigate/black/transfer.mjs`. Поток tar между SSH-процессами
   остаётся бинарным, секреты не записываются на рабочей станции; SQLite передаётся
   только после подтверждения остановленного White. Проверяются оба кода передачи.
5. На Black остановить staging, сохранить его скачанный Jina-кеш в локальном config,
   преобразовать перенесённый config через `prepare.py` без `--staging`, закрепить digest
   образа в `.env`. Проверить Compose; выполнить `systemctl enable --now media-frigate.mount`
   и `systemctl enable --now frigate-black.service`. После появления всех камер включить
   `systemctl enable --now krt-camera-watchdog.timer`.
6. На White: `sudo python3 frigate/black/deploy.py white-switch --commit <main SHA>`.
   Команда проверяет три камеры Black, заменяет только Frigate upstream в обоих текущих
   HTTP vhosts, устанавливает stream proxy, проверяет и перечитывает nginx. Basic auth,
   сертификаты, домены и остальные upstream сохраняются.
7. После независимой приёмки остановить оба rollback timer и подтвердить их inactive.
   На White выполнить `sudo python3 frigate/black/deploy.py white-finish`. Прежние timers
   становятся disabled, fence остаётся; rollback-white удаляет fence после восстановления
   работающего White recorder.
8. После обновления OCR API и ASR с idle unloading на Black выполнить
   `sudo python3 frigate/black/deploy.py captions`. Команда проверяет наличие caption API,
   создаёт worker через Compose и подтверждает его running. Прочитать его журнал и SQLite,
   затем точное описание завершённого события через Frigate API.

Для восстановления без доступной NVIDIA-карты преобразовать config с `prepare.py --cpu`
и записать в `/opt/frigate/runtime.env` строку
`COMPOSE_FILE=/opt/frigate/compose.yml:/opt/frigate/compose.cpu.yml`. После проверки
объединённого Compose restart службы использует профиль без GPU reservations и NVIDIA
environment. Образ содержит CPU ONNX provider; GPU runtime не требуется. Удаление этой
строки и преобразование config без `--cpu` возвращают штатный GPU-профиль.
