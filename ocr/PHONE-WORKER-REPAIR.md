# Возобновление OCR телефонного архива на Windows

Анимация из 100 кадров не должна отправляться одним OCR-запросом: распознавание
всех кадров может превысить клиентский тайм-аут 900 секунд. Повтор такого запроса
не сохраняет уже обработанные кадры и блокирует следующие файлы очереди.

`repair_phone_worker.py <путь к phone_backup_ocr.py>` адресно обновляет worker
`2026-10-01-text-json-v5` до `2026-10-08-frame-resume-v6`:

- Все многостраничные изображения идут через существующую обработку отдельных
  кадров и fragment-cache; исходные кадры и результаты не исключаются.
- Небольшой кадр получает ограниченный бюджет токенов уже на первом запросе.
  Усечённый ответ по-прежнему требует восстановления и не считается успешным.
- Среди файлов одинакового приоритета сначала идут менее обработанные файлы.
  Повторяемая транспортная ошибка одного файла не перекрывает остальную очередь.

Перед применением остановить точный scheduled task и убедиться, что его
`phone_backup_ocr.py` больше не работает. Другие OCR-клиенты и Black API не
перезапускать. Выполнить patcher на Windows, затем запустить тот же scheduled
task с прежними аргументами. Повтор patcher идемпотентен; неизвестная или
частично изменённая версия отклоняется до записи.

Проверка: единственный worker, версия v6 в `status.json`, рост `done` в прежней
`checkpoint.sqlite`, новые файлы `json/` и `text/`. `Running` или HTTP health без
новых результатов не подтверждают восстановление очереди. После перезагрузки
должен использоваться прежний startup trigger этой задачи.

Для отката остановить ту же задачу и выполнить patcher с `--rollback`, затем
снова запустить её. Обратная замена проверяется до записи и восстанавливает
исходный код без отдельной копии. Checkpoint и результаты не меняются.
